## やったこと

架空の請求書と納品記録を渡して、無料版のGeminiに突き合わせのチェックをさせました。送ったのは1回だけ、作り直しはさせていません。今回の回答ではコード実行が使われました。

請求書には間違いを6件仕込みました。数量の転記ミス、値引きの未反映、単価の取り違え、納品記録にない架空請求、消費税の端数処理の誤り、合計の足し算ミスです。

結果は、6件中5件を検出。修正値（小計316,339円・消費税31,633円・合計347,972円）はすべて正解で、誤指摘は0件でした。見落としたのは、消費税の端数処理の1円だけです。

## 照合結果（6件中5件を検出）

| 検証ポイント | 結果 |
|---|---|
| 数量の転記ミス | 検出（正しい数量・金額まで正確） |
| 値引き未反映 | 検出（契約単価2,250円・27,000円まで正確） |
| 単価の取り違え | 検出（720円・10,800円まで正確） |
| 架空請求19,800円 | 検出（納品記録にない請求。逆方向の照合も通った） |
| 消費税の端数処理 | 見落とし（正しい税額31,633円に置き換えただけで、請求書側の端数処理の誤り自体には触れていない） |
| 合計の足し算ミス | 検出（請求書自身の数字では393,183円になることまで明示） |
| 誤指摘ゼロ | 適合（分割納品の合算、税込表記の行、値引きの切り捨て、品名の表記ゆれを、すべて正しく素通り） |
| 修正値 | 適合（小計316,339円・消費税31,633円・合計347,972円、すべて正解） |

月次レポートの実測でもそうでしたが、金額の大きい間違い（架空請求19,800円、数量ミス19,200円）は全部拾うのに、落ちるのは「正しい値に置き換えれば消えてしまう小さな誤り」でした。

## 受け取り側のチェック

- AIが直した数字は合っていることが多い。でも、直し方のルール違反（端数処理の方法など）までは見ていないことがある
- 端数処理のような「処理方法」のチェックは、別途頼むか人が見る
- 合計は請求書自身の数字でも検算する

## 実測の条件と注意

- 無料版Gemini（自動モード）、送信1回、再生成なし
- 会社名・品名・金額はすべて架空のもの
- 試行は1回だけ（n=1）なので、毎回同じ結果になるとは限りません
