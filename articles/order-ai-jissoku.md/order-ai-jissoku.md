## やったこと

架空の在庫データ14品目と、発注ルールを書いた社内メモを渡して、無料版のGeminiに発注リストを作らせました。送ったのは1回だけ、作り直しはさせていません。

ルールは全部ことばで明示しました。在庫と使用見込みと発注済みを合わせた「見込み在庫」が発注点を下回ったら発注する、発注点ちょうどは発注しない、不足分は発注単位に切り上げる、廃番は除外する、といった内容です。

結果は少し変わっていて、回答の中に発注リストが3版並びました。最終版は、発注する9品目・発注しない5品目の判定、数量、金額、合計105,130円まで、検証した8点すべて正解です。ただ最初の版は、発注すべき9品目のうち5品目しかなく、合計も43,000円でした。受け取る側が最初の表をそのまま使えば、4品目・62,130円分の発注漏れになります。

## 照合結果（最終版は8点すべて正解）

| 検証ポイント | 結果 |
|---|---|
| 発注のきっかけを定数にしない | 適合（見込みが発注点を上回る品目は発注しない、理由も正しい） |
| 発注点ちょうどの境界 | 適合（見込み12＝発注点12で発注しない） |
| 発注済みの合算で判定が消えるケース | 適合（発注済みを足すと見込み25で、発注しない） |
| 発注済みの合算で数量が決まるケース | 適合（最終版。ただし途中版では2回、誤った扱いが出た） |
| 発注単位への切り上げ | 適合（42→50冊、23→24個） |
| 大きな発注単位の切り上げ | 適合（170→200枚、不足3→20巻。定数を大きく超えてもルールどおり） |
| 廃番の除外 | 適合（全版を通じて発注せず、代替品の追加もなし） |
| 合計の検算 | 適合（最終版105,130円。ただし回答内には43,000円と47,050円の合計も並んでいる） |

## 受け取り側のチェック

- 生成型で手順が多い頼み方は、最初の版を信用しない。使うのは最終版だけ
- 最終版の明細は自分で足し直す。回答の中に複数の合計が並ぶことがある
- 途中の版で理由が変わった品目は、最終版の理由を採用する

残業代や経費精算のような「判定・照合型」は単一の回答で満点でしたが、今回のような「生成型＋手順が多い」頼み方では、最終的にはルールどおりにたどり着いても、途中の版が全部出力に残りました。

## 実測の条件と注意

- 無料版Gemini（自動モード）、送信1回、再生成なし
- 品目・単価・在庫数はすべて架空のもの
- 試行は1回だけ（n=1）なので、毎回同じ結果になるとは限りません
